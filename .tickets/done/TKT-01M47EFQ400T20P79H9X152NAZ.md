## Description

Bring Forgejo up to what Vuoro already does on GitLab: human-directed posting, a verdict at submit, and the editor's push, both onto the person's own branch and as a stacked draft pull request. Forgejo reading, checkout, agent reviews, summaries, and the inbox are already done (TKT-01M3ZKGRZBBS869259MBA818NQ and the D34 inbox slices). What is left is everything that writes.

### Where it stands, 2026-10-06

- `forge/forgejo` implements `forge.Provider`, `forge.Discoverer` and `forge.FactsReader`. It reports empty `Capabilities()`, so it implements neither `forge.Writer` nor `forge.Stacker`.
- `app/editor.go` refuses a Forgejo change with "vuoro opens a stacked merge request on GitLab only, so far". That refusal blocks both D39 (stacked fix PR) and D41 (push to your own branch), because both go through `StackTarget`.
- `web/src/change.tsx` hardcodes "Forgejo posting is not available yet" instead of reading capabilities.
- `forge.Writer` has no "request changes" verdict on any forge.

### What the API allows

The internal instance runs Forgejo 15.0.3 (gitea-1.22 API). Its swagger offers:

- `POST /pulls/{n}/reviews`, including event `PENDING`
- `GET`, `POST` and `DELETE` on `/reviews/{id}`, where a `POST` submits with `COMMENT`, `APPROVED` or `REQUEST_CHANGES`
- `GET` and `POST` on `/reviews/{id}/comments`
- `GET` and `DELETE` on `/reviews/{id}/comments/{c}`
- `/reviews/{id}/dismissals` and `/reviews/{id}/undismissals`

The swagger has no endpoint to edit a review comment, to reply in a thread, or to resolve a conversation. The model does not match GitLab's in places: a review carries one general body, and an approval is withdrawn by dismissal, not revocation. The spike settles each of these before posting is built.

### Order

1. The spike against a sandbox PR. Everything below depends on it.
2. A verdict at submit, and capabilities fine enough to hide what a forge cannot do. These are shared-boundary changes and touch GitLab too.
3. The Forgejo writer (TKT-01M3W4HX4CJE62G9R124EV5PT4) and the Forgejo stacker, which can be built in parallel.
4. The inbox and turn behaviour after Forgejo writes. The writer ticket's acceptance criteria cover it.

Every write stays a protected, explicit action of the person's. Agents only draft, and the editor never holds a token or pushes for itself (docs/plan.md section 6.3).

## Acceptance criteria

- [x] A Forgejo PR can be reviewed, posted, and given a verdict from vuoro, with unsupported actions hidden
- [x] The editor's fixes reach a Forgejo PR by the same two routes as on GitLab: pushed to my own branch, or as a stacked draft PR
- [x] No control in the UI is chosen by forge name; every write control follows the forge's capabilities

## Summary

Forgejo is at parity with GitLab for posting, verdicts, and the editor's push. All five children are done:
- TKT-01M47EG9BHW0HBVFBTSBB1915X: the write spike
- TKT-01M3W4HX4CJE62G9R124EV5PT4: posting through the shared boundary
- TKT-01M47EG9CSRDZ2HKANYN30XBAY: the verdict on submit
- TKT-01M47EG9E07Y4N1J34S5VDDC5N: write actions follow capabilities
- TKT-01M47EG9F7HZ7C3EPYF2TJMEYV: the editor's push

### Evidence, from the 2026-10-08 audit
- **Posting and verdicts.** `forge/forgejo/write.go` reports Drafts, Reply, Approve and RequestChanges, and leaves out resolve, unapprove and suggestions, which Forgejo cannot do. These tests cover it:
  - `TestDraftsStayLocalUntilOneReviewPublishesThem`
  - `TestApproveAndWhatForgejoCannotDo`
  - `TestARetryAfterAVerdictPostsOnlyTheReplies`
  - `app/caps_test.go` `TestAWriteTheForgeCannotDoIsRefused`

  `TestLiveWrite` passed on the sandbox on 2026-10-06.
- **The editor's two routes.** `forge/forgejo/stack.go` implements `forge.Stacker`, and `app/editor.go` refuses only a forge without one. `TestLiveStack` passed live on 2026-10-06 and covers both the own-branch push and the stacked draft PR.
- **No write control is chosen by forge name.** Every write control in `web/src` follows the capabilities: `confirm.tsx`, `comments.tsx`, `triage.tsx` and `change.tsx`. The remaining kind checks only pick display words, link shapes, the forge picker, and which paths count as CI files. The GitHub adapter (#23 to #25) relied on this and needed no UI change for its writes.

`CGO_ENABLED=0 go test ./...` passed on main at fa91bac. The epic's "Where it stands, 2026-10-06" section in the description is history: each problem it lists has since been fixed.
