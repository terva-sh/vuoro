## Description

A run of mode `ask`, pinned to the change's exact base and head read fresh from the forge, with the scope `change` or `since_review` and the range rules of a summary (section 6.4). Its first message is a canned prompt or the person's question, and the person can follow up any number of times on the same session. An ended session is resumed with `Spec.Resume`, so a conversation carries on after a restart. When the change's head moves, the run is marked stale with both heads. Summary runs (mode `summary`) are read as conversations whose prompt is `explain`, in place.

The session has the reviewer lockdown: Read, Grep, Glob, no shell, no web, no extensions, none of the person's MCP servers, and no drafts server. The context server comes in its own ticket.

Design: docs/plan.md section 6.11, D68.

## Acceptance criteria

- [x] An ask run pins the fresh base and head, with scope change or since_review
- [x] The person can follow up on the same session, and after a restart it resumes
- [x] A moved head marks the conversation stale and names both heads
- [x] Summary runs read as explain conversations, unchanged on disk
- [x] The session's tools are Read, Grep, Glob and the context server only, and a test proves it

## Implementation plan

- review/ask.go: AskMode, Ask{Prompt,Title,Question} on Run (record + view). StartAsk validates the exact range as StartSummary does (reusing SummaryRange in r.Summary and summaryInput), then runs through the generic m.start/prepare/begin/pump path, so Say, Stop and resume after a restart are the generic ones. prepare builds the first message (question, range, untrusted title, input) after the checkout.
- launch: a drafts.Summary-role session gets no MCP server and no drafts token. load restores its askPrompt spec.
- AsksOf(ref): the change's ask runs and its summary runs, newest first; a summary is given Ask{Prompt: explain} in the listing only, so its record is unchanged.
- app: POST /api/asks starts one (a prompt name resolved from the prompt list, or a free-form question); POST /api/changes/asks lists a change's. Ask runs answer only the generic "", close, sessions and head routes, and stay out of /api/runs. Stale is the existing POST /api/runs/{id}/head, which names both heads.
- tests: spec has no MCP server and no editor; follow-up on the same session; reload then follow-up resumes with the ref; summary listed as explain with its file byte-identical; routes and window guard.
