## Description

goreleaser releases, as other terva-sh tools have them, and `vuoro self-update`,
as git-ticket has it. Decide macOS signing and notarization here.

## Acceptance criteria

- [x] A tagged release publishes archives for macOS, Linux, and Windows
- [x] The macOS signing decision is recorded
- [x] The GitHub workflow runs on a v* tag alone, and verifies the archives before it publishes them (D74)
- [x] Each archive names its tag and commit through the build information, and carries LICENSE, THIRD_PARTY_LICENSES and README-release.md

## Implementation plan

Follow git-ticket-canvas: .goreleaser.yaml (cgo off, linux/darwin amd64+arm64, windows amd64, -trimpath, archives with LICENSE, THIRD_PARTY_LICENSES, README-release.md, checksums.txt, release disabled). Version from debug.ReadBuildInfo (main.go buildVersion), no -X stamp. THIRD_PARTY_LICENSES generated by scripts/third-party-licenses.py with a --check in the gate and internal CI. scripts/verify-release.py and scripts/rehearse-release.py, with just release-check, release-snapshot, release-rehearse. .github/workflows/release.yml on a v* tag only: gate, goreleaser --skip=publish, verify, then gh release create from a draft with the tag's notes. release_config_test.go holds the rules. docs/releasing.md, plan 9.1, README, AGENTS.md.
